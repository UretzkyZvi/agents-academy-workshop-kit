Step 3

Plan signal points before connecting accounts.

Gmail, Calendar, and CRM are where people get stuck. Start with exported CSVs or sample rows. Prove the workflow first. Connect APIs later.

Gmail

Best first test: export or copy a few emails from one label.

Safe scope: read-only, one label, no sending.

Calendar

Best first test: export upcoming events or create a sample event list.

Safe scope: read-only, next 7-14 days.

CRM

Best first test: export a filtered list of deals, clients, or renewals.

Safe scope: read-only filtered pipeline.

Spreadsheet

Best first test: use a sheet as the signal queue.

Safe scope: manual import/export first.

Step 4

Run the local-first signal test.

These commands use the sample CSV. No Gmail, Calendar, CRM, or model API required.

Try the sample workflow

mkdir -p outputs
python scripts/normalize_signal_csv.py examples/sample-signals.csv outputs/normalized.csv --source sample --id id --date date --person person --organization organization --title title --body body --status status --url url
python scripts/make_signal_review_brief.py outputs/normalized.csv outputs/review-brief.md --workflow "Client intake follow-up"

What you get

A normalized CSV and a markdown review brief an agent can summarize, classify, or draft from.

What it will not do

It will not send email, update CRM, or touch private accounts. That comes only after the workflow proves useful.
